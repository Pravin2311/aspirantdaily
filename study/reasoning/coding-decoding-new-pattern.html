New-Pattern Coding-Decoding: Rule-Based Word Codes, Conditional Symbols and Sentence Codes by Elimination

What the code is built from • Finding the rule from two examples • Condition-based symbols • Position-sum and product codes • Sentence codes by elimination

Banking 📅 Last updated: 2026-11-02

In classic coding-decoding, every letter is shifted by the same amount. New-pattern questions instead build a short code from a few properties of the word. Once you know the usual ingredients, most rules can be spotted in under a minute:

  • Length: the number of letters, written as a digit.
  • Neighbours: the letter just before or after the first or last letter.
  • Opposite letters: A↔Z, B↔Y and so on; each pair of positions adds to 27.
  • Positions: the sum or product of letter positions (A = 1 … Z = 26).
  • Conditions: a symbol that depends on whether the word starts with a vowel, has an even number of letters, and so on.

Keep the position table handy; the EJOTY trick gives any position instantly (E = 5, J = 10, O = 15, T = 20, Y = 25).

Write each code under its word and compare one position at a time. Ask: is this character a letter, a digit or a symbol? If it is a letter, how does it relate to the word's first or last letter? If it is a digit, does it match the length?

Worked example 1: a three-part code

Given: STONE → T5D and PEN → Q3M. In each code, the first character is the letter after the word's first letter (S→T, P→Q), the digit is the length, and the last character is the letter before the last letter (E→D, N→M). Applying the rule to PLANT gives Q5S.

Worked example 2: opposite letters

Given: CAT → XZG. C (3) → X (24), A → Z, T (20) → G (7): each letter is replaced by its opposite. So BOX becomes YLC.

Always test your rule on every example. A rule that fits only one of them is wrong.

Many bank-exam versions add a condition: the word's code changes depending on a property of the word. Read the conditions in order and apply the first one that fits, unless the question says otherwise.

Worked example 3: vowel or consonant start

Rule: if the word starts with a vowel, the code is # + number of letters + the opposite of the last letter. If it starts with a consonant, use $ instead of #. APPLE starts with a vowel, has 5 letters and ends in E, whose opposite is V, so APPLE → #5V.

Worked example 4: the consonant branch

MANGO starts with a consonant and ends in O, whose opposite is L. MANGO → $5L.

Typical conditions include a vowel or consonant at the start or end, an even or odd number of letters, and whether the first letter comes before or after M. Write the condition you used next to each answer so you can recheck it quickly.

When a word turns into a number, try the simplest arithmetic first: the sum of positions, then the product of the length and one position, then the sum of the first and last positions.

Worked example 5: sum of positions

CAT → 24. C = 3, A = 1, T = 20, and 3 + 1 + 20 = 24. A second example confirms it: DOG = 4 + 15 + 7 = 26.

Worked example 6: length times first position

BLUE → 8. BLUE has 4 letters and B = 2, so 4 × 2 = 8. The sum of positions (2 + 12 + 21 + 5 = 40) does not fit, so the product rule is the one to use.

Here each word of a sentence has a code word, but the codes are jumbled. Do not try to decode everything; find the word shared by two sentences and the code shared by the same two.

Worked example 7: three sentences

"sun is bright" = la pa ko; "sky is blue" = ko mi ra; "bright blue sun" = pa ra la.

"is" appears in the first two sentences, and the only code they share is ko. "blue" appears in the second and third, and they share only ra, so "sky" = mi. The first and third share "sun" and "bright" and the codes la and pa, so those two cannot be told apart without more data. A good answer to "code for bright?" is "la or pa".

Common traps: trusting a rule tested on only one example; mixing up "letter before" and "letter after"; applying the wrong branch of a condition; and forcing an answer when the data leave two possibilities. For letter-shift codes, see letter-shift coding.

Q1. In a code, PLANT is written as Q5S: the letter after the first letter, then the number of letters, then the letter before the last letter. How is GRAPE written? easy

✅ Answer: (a) H5D

💡 Explanation: G + 1 = H, GRAPE has 5 letters, and E − 1 = D, so the code is H5D.

Q2. If CAT is coded as 24 by adding letter positions, what is the code for DOG? easy

✅ Answer: (b) 26

💡 Explanation: D = 4, O = 15 and G = 7, which add up to 26.

Q3. Each letter of a word is replaced by its opposite letter (A↔Z, B↔Y, …). What is the code for LAMP? medium

✅ Answer: (d) OZNK

💡 Explanation: Opposite pairs add to 27: L(12)→O(15), A→Z, M(13)→N(14), P(16)→K(11). The code is OZNK.

Q4. In a code, CAT = 24 and DOG = 26. What is SUN? easy

✅ Answer: (c) 54

💡 Explanation: The code is the sum of letter positions: S = 19, U = 21, N = 14, total 54.

Q5. A code multiplies the number of letters in a word by the position of its first letter, so BLUE = 8. What is TIGER? medium

✅ Answer: (a) 100

💡 Explanation: TIGER has 5 letters and T is the 20th letter, so the code is 5 × 20 = 100.

What is new about new-pattern coding-decoding?

Older questions shift every letter by a fixed amount. Newer bank-exam questions build a short code from properties of the word, such as its length, its first and last letters, vowels or letter positions, often with a condition that changes the symbol.

How many examples do I need to find the rule?

Usually two. Compare the same position in two codes and ask what changed in the words. One example often fits several rules, so test your guess on the second example before answering.

What is the fastest way to handle sentence codes?

Find a word that appears in two sentences and the code common to the same two. Fix it, strike it out of both, and repeat. You rarely need to decode every word.
